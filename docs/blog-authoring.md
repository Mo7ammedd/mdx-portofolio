# Writing blog articles

Keep one `# Title` in each `app/blog/<slug>/page.mdx` file. The compiler moves
it into the article header and uses the metadata description as a short
introduction. The authored title may differ from the SEO title. Use `##` for
sections and `###` for subsections; their links and collapsible contents groups
are generated automatically.

## Code blocks

Fenced code supports an optional filename, highlighted lines, and line numbers:

````mdx
```sql title="posts.sql" {3-4} showLineNumbers
SELECT id, created_at
FROM posts
WHERE (created_at, id) < (:created_at, :id)
ORDER BY created_at DESC, id DESC
LIMIT 10;
```
````

Line numbers and highlighting are visual annotations; copying a block copies
only the code. Omit `title`, the line selection, or `showLineNumbers` when they
do not help explain the example.

## Callouts and steps

These components are available in every article without imports. Keep blank
lines around Markdown inside the components.

```mdx
<Callout type="success" title="Key takeaway">

Give a cursor a unique tiebreaker and a matching index.

</Callout>

<Steps>
<Step title="Find the starting position">

Seek to the cursor in the index.

</Step>
<Step title="Read a page">

Read the next `LIMIT` rows.

</Step>
</Steps>
```

Callout types are `info`, `warning`, `success`, and `error`. Use a specific title
such as “Common mistake” and reserve callouts for material readers should notice.

## Alternative examples

Wrap each alternative in a `Tab`, with a matching label in the same order:

```mdx
<Tabs label="Implementation language" labels={['C#', 'TypeScript']}>
<Tab>

The C# example goes here, including fenced code if needed.

</Tab>
<Tab>

The TypeScript example goes here.

</Tab>
</Tabs>
```

Left/Right arrow keys switch tabs; Home/End select the first/last one. Every
panel remains visible with its label when JavaScript is disabled. Use section
headings outside tabs so contents links always lead to visible content.

## Images

Markdown images receive a frame and an accessible zoom control. `Cover` adds a
caption that explains the image, without repeating the alt text underneath:

```mdx
<Cover
  src="/blog/pagination-strategies/offset-pagination-mechanics.webp"
  alt="OFFSET scanning and discarding rows before the requested page"
  caption="Each deeper page requires the database to scan more rows."
/>
```

Supply `width` and `height` for images absent from `lib/blog-image-metadata.ts`.
Zoom opens a native dialog with keyboard focus contained inside it. Escape or
the close button returns focus to the image link; the link opens the original
image directly when JavaScript is disabled.

## Search and saved reading positions

The static `/blog/search-index.json` endpoint indexes article prose, code, and
authored block titles/captions during the build. Search loads that index on demand
and links to the same heading IDs generated by the article compiler. JavaScript
expressions and metadata exports are excluded. Keep section headings descriptive;
use the standard Markdown heading syntax so navigation and search stay in sync.

Reading progress saves the active section in this browser after a short delay.
Returning readers can follow a reminder; the page never automatically scrolls
to a saved position. Explicit incoming fragments take precedence. Finishing an
article clears its position, and removed sections or records older than 90 days
are ignored. Storage failures do not interrupt reading.

## Interactive examples

`<PaginationDemo />` embeds the pagination model used in the pagination article.
It compares entry counts for a single page fetch in an indexed, stable dataset
with a known cursor. Keep its assumption text with the model. The plain HTML
fallback explains a sample comparison when JavaScript is disabled.

## Reading paths and freshness

Edit `lib/reading-paths.ts` to curate ordered articles, outcomes, and prerequisites.
Paths appear at `/blog/paths`, in each article's expandable path panel, and in the
next-step link at the end of an article.

Set `modifiedTime` in an article's metadata when its content changes meaningfully.
The header and article list show a later update date; a site rebuild does not
change it. Add version labels in `lib/blog-freshness.ts` only after running scoped
example checks. Include a matching `## Verified Examples` section, the observed
runtime/version, date, scope, and reproducible evidence. See
[the verification record](verification/2026-09-16.md).

## Nginx routing playground

`<NginxRoutingDemo />` renders the location matching model used in the Nginx
article. Readers can enter a path or HTTP URL, try supplied examples, and toggle
the `^~` modifier on `/assets/`. The decision trace covers exact matches, the
longest prefix, and regexes in declaration order. Its scope is flat locations
on a case-sensitive server, with default slash merging and no rewrites.

## Glossary terms

Use `<Term id="mvcc">MVCC</Term>` inline at a useful first mention. Definitions
live in `lib/blog-glossary.mjs`. A term opens a small native popover with a
definition and example; `/blog/glossary` contains the full list and article
references. Keep headings outside the popover and avoid repeating the control
at every occurrence of a term.

## Practical exercises

Add `<Exercise id="boxing-copy" />` beneath a Markdown section heading. Questions,
choices, explanations, and review links live in `lib/blog-exercises.mjs`. Each
exercise is optional, supports keyboard selection and retry, and includes a
native disclosure with the answer when JavaScript is disabled. Neither answers
nor scores are recorded. Search indexes the referenced question and explanation.

## Bookmarks and completion

“Save article” adds a post to `/blog/saved`. “Mark as read” at the end of an article
updates its reading path; clicking it again clears completion. These flags are
independent of each other and of the existing section resume position. They
persist in local browser storage and synchronize between tabs. If storage is
blocked, controls work for the current visit and explain that limitation.

## RSS rendering

The RSS feed is generated at build time from the parsed MDX tree. It preserves
native Markdown and tables, code filenames, captions, callouts, steps, and every
tab panel. Demos get a static worked example and a link back to the interactive
article; exercises include their answer, and glossary definitions appear at the
end of the feed entry. Imports and expressions are never evaluated. Attribute
values can be literal strings or static literal arrays, such as tab labels.

When adding a new custom MDX component, add its readable feed representation in
`lib/blog-feed.ts`. Feed URLs are absolute, code is escaped, and update timestamps
come from article metadata rather than the time the feed is requested.
