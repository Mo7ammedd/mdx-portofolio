# Blog example verification — September 16, 2026

These checks support the scoped version labels on three articles. The observed
versions came from the installed runtimes, not inferred compatibility ranges.

## PostgreSQL pagination

Observed: PostgreSQL **18.6**, x86_64 Linux. Ran
[`pagination.sql`](../../scripts/verify-blog/pagination.sql) in a fresh local
cluster with TCP listening disabled. The fixture creates a temporary 103-row
table, tied timestamps, and a matching `(created_at DESC, id DESC)` index.

Passed: OFFSET/composite-cursor equality across 11 pages, complete traversal
without skipped or duplicated rows, the final partial page, cursor exhaustion,
and a timestamp-only cursor that demonstrates the missing-tiebreaker problem.
No benchmark timings or database versions other than the one above were certified.

Reproduce from the repository root with PostgreSQL installed:

```sh
blog_verify_dir=$(mktemp -d /tmp/blog-postgres-XXXXXX)
initdb -D "$blog_verify_dir/data" -A trust -U blog_verifier --no-locale
pg_ctl -D "$blog_verify_dir/data" -l "$blog_verify_dir/server.log" \
  -o "-F -k $blog_verify_dir -c listen_addresses='' -p 55437" -w start
psql -h "$blog_verify_dir" -p 55437 -U blog_verifier -d postgres \
  -f scripts/verify-blog/pagination.sql
pg_ctl -D "$blog_verify_dir/data" -m fast -w stop
```

## C# and ASP.NET Core

Observed: SDK **10.0.112**, .NET **10.0.12**, ASP.NET Core **10.0.12**.
Ran [`Program.cs`](../../scripts/verify-blog/dotnet/Program.cs) in Release mode.
The harness reports actual runtime versions and throws on a failed assertion.

Passed for the boxing article: copying a value into a box, exact-type unboxing,
an invalid cast, and equivalent stored values in `ArrayList` and `List<int>`.
This checks behavior rather than allocation sizes or throughput.

Passed for middleware: a local Kestrel server received two real HTTP requests.
Assertions checked request/response order, one conventional middleware instance,
two transient `IMiddleware` instances, the endpoint response body, and the timing
header written through `OnStarting`. The article's inline example was corrected
to register that callback before downstream code can start the response.

```sh
dotnet run --project scripts/verify-blog/dotnet/BlogExamples.csproj \
  --configuration Release --artifacts-path /tmp/mdx-blog-dotnet-verification \
  --no-launch-profile
```

The project allows missing SDK package-pruning metadata for distribution-packaged
SDKs. It uses the installed ASP.NET Core framework reference and no NuGet packages.
The web server listens on an ephemeral loopback port and shuts down after the checks.

Add or refresh a label in `lib/blog-freshness.ts` only after rerunning the relevant
checks. Record its date, runtime, and scope, and keep the article's verification
section and meaningful `modifiedTime` in sync.
